# TrollStore + TrollFools 部署指南（不越狱）

适用：iPhone 12 Pro Max / iOS 15.4.1 / 已装 TrollStore（巨魔）。
这条路线**只需要一个文件**：CI 产出的 `WXKit.dylib`（`.deb` 是给越狱用的，你用不到）。

---

## 0. 先理解这条路线卡在哪

| 事实 | 影响 |
|---|---|
| TrollStore 本身不带注入 | 注入靠 TrollFools（TrollStore 应用）把 dylib 塞进微信的 App 包 |
| App Store 版微信是 **FairPlay 加密**的 | 注入工具改的是 Mach-O 的 load command 并要重新签名，加密包上这一步成功率低、常见结果是启动闪退 —— 所以实践中要用**解密版微信 IPA** |
| 本插件**不链接任何越狱库** | 纯 ObjC runtime 方法交换，所以在未越狱进程里也能正常工作（CI 会强制校验这一点） |
| 设置界面不依赖 PreferenceLoader | 入口是插件自己的悬浮球，未越狱下也能改配置 |

所以顺序是：**先拿到解密版微信 IPA → 装进 TrollStore → 再用 TrollFools 注入 dylib**。

---

## 1. 开干之前：备份

注入、覆盖安装微信都有丢聊天记录的可能，先做备份：

1. 微信 → 我 → 设置 → 通用 → 聊天记录迁移与备份 → 备份到电脑（最稳）；
2. 或者对整机做一次加密备份（iTunes / Apple 设备 / 访达）。

---

## 2. 拿到解密版微信 IPA（两条路）

### 路线 2A：借一次临时越狱自己解密（推荐，来源可信）

你的机型与系统正好在 Dopamine 支持范围内（A12–A15 / iOS 15.0–15.4.1）：

1. 用 Dopamine 越狱（rootless）；
2. 越狱环境里用解密工具导出微信 IPA：
   - `frida-ios-dump`（`dump.py -o WeChat.ipa 微信的 bundle id`），或
   - `bagbak`（`bagbak com.tencent.xin`）；
3. 用 Dopamine 的 **Restore Rootfs** 回到未越狱状态；
4. 现在你手上有一个**自己解密的** `WeChat.ipa` —— 来源可控，没有第三方塞后门的问题。

> 这一步只是一次性操作：解密完成后就不需要越狱了，之后一直走 TrollStore。

**选版本时注意**：iOS 15.4.1 只能跑最低系统要求 ≤ 15.4.1 的微信版本。
先确认一下 IPA：

```bash
unzip -p WeChat.ipa 'Payload/*.app/Info.plist' > /tmp/wx.plist
# 用任意 plist 工具看 MinimumOSVersion，必须 <= 15.4.1
# 另外顺手看一眼 CFBundleShortVersionString，这个版本号后面要发给我
```

太新的微信装不上（提示需要更高系统），不是插件的问题。

### 路线 2B：第三方解密源

网上有现成的"解密版微信 IPA"。能用，但**你不知道里面被改过什么**，风险自负。
至少做到：装之前核对文件哈希；不要用别人改过的"增强版/共存版"；装完先用自己机器的抓包/权限列表粗查一遍。

## 3. 安装与注入

### 3.0 先用探针验证注入链路（强烈建议，30 秒）

CI 产物里除了 `WXKit.dylib`，还有一个 **`WXKitProbe.dylib`**（约 40 行，不挂任何 hook、不改任何行为）。
它的唯一作用是回答："dylib 到底能不能被注入进微信？"

先用它，能省掉一大轮瞎试：

| 结果 | 说明 | 下一步 |
|---|---|---|
| 微信里出现**绿色横幅「WXKit 探针已注入」** | 注入链路完全通了（解密包 + TrollFools + 重签名都 OK） | 再注入完整版 `WXKit.dylib` |
| 横幅不出现，但 TrollFools 显示已注入 | 大概率是签名问题 | 换 `WXKit-signed.dylib` 再注一次 |
| 微信闪退 / 起不来 | 包还是加密的，或重签名不完整 | 回到第 2 节换解密 IPA |
| 探针和完整版一起注 | 也可以，两者不冲突 | 看到横幅就说明链路 OK |

点横幅可以看到详细信息（宿主 bundle id、微信版本、构建号、容器路径）；探针还会在微信容器里写一个
`Library/Application Support/WXKit/probe.txt`。

**为什么值得先做**：探针不含任何"猜测"，所以它的失败必然是注入环节的问题；
而完整版失败则可能是注入问题，也可能是候选类名不对——先注探针能把两者分开。

### 3.1 注入完整版

1. **装微信**：把解密版 `WeChat.ipa` 用 TrollStore 安装（bundle id 相同，会覆盖 App Store 版；数据容器通常保留，但仍然建议先做第 1 节的备份）。
2. **先裸跑一次**：打开微信，确认能正常登录、能收发消息、能收到推送。这一步失败就别往下做，先解决安装本身。
3. **传 dylib 到手机**：CI 产物 `WXKit.dylib` 用 AirDrop 或"存到文件"放进「文件」App。
   - 如果某个环节提示需要签名，用同一产物里的 `WXKit-signed.dylib`（CI 已用 `ldid -S` 生成 ad-hoc 签名副本）；
   - 通常 TrollFools 自己会签名，未签名的那份也能用。
4. **注入**：打开 TrollFools → 找到微信 → 注入（Inject）→ 选择 `WXKit.dylib` → 等它重签名完成。
5. **重启微信**：完全退出微信（后台卡片上滑掉）再打开。
6. **看结果**：微信里出现一个 `WX` 悬浮球（贴边、可拖动）。

---

## 4. 第一次运行要做的三件事

1. 点悬浮球 → **运行自检**：报告里每一项都应该是 ✅；
   - 「新消息回调已挂上」是 ❌ 的话，说明你这版微信的类名/方法名和候选不一致 —— 见第 6 节；
2. 设置 → **导出类名与方法**，生成 `wxkit-classes.txt`；
3. 设置 → **导出文件**，把自检报告 / 类名 / 日志一次性发出来（AirDrop、存文件、发给维护者都行）。

---

## 5. 怎么确认真的在工作

| 想验证 | 做法 | 应该看到 |
|---|---|---|
| 消息管线通了 | 让朋友发一条文本 | 日志里出现 `[pipeline] 新消息字段转储`（前 3 条）与 `[store] 记住 …` |
| 防撤回 | 让朋友发一条再撤回 | 屏幕内提示原文；设置 → 查看撤回记录里有这条 |
| AI 回复 | 配好 Key 后开开关，私聊发一句 | 日志 `[ai] 触发自动回复` → 对方收到回复 |
| 悬浮球没了 | 长按悬浮球 → 缩到最小 | 变成半透明小点，点它仍能进设置（不会把自己锁在外面） |

---

## 6. 自检有 ❌ 怎么办

微信每个大版本都会改内部命名。本项目所有对接点都是「候选名列表 + 存在才挂」，
而且**不用重新编译注入**：设置 → **适配（候选名覆盖）** → 粘贴真实名字 → 保存 → 点「重试挂载消息回调」。

把 `wxkit-classes.txt` 发我，我可以直接给你一条适配好的覆盖文本；
或者按 **[HOOKS.md](HOOKS.md)** 的「★ 最快路径」自己填。适配状态记录在 **[VERSIONS.md](VERSIONS.md)**。

## 7. 故障对照

| 现象 | 原因 | 处理 |
|---|---|---|
| 注入后微信一打开就闪退 | 用了加密的 App Store 包，或重签名不完整 | 换解密 IPA 重装；注入时用 `WXKit-signed.dylib` |
| 微信能开但没有任何变化 | TrollFools 注入没生效（列表里没有 WXKit） | 重新注入；确认注入的是微信而不是别的 App |
| 悬浮球一直不出现 | 冷启动时还没有 keyWindow（插件已做退避重试 + 回前台自愈） | 切后台再回前台一次；仍不行则导出日志看 `[ui]` 记录 |
| 收不到推送 / 通知异常 | 覆盖安装后 entitlements 与 App Store 版不一致 | 换能保留原始 entitlements 的 IPA；必要时回滚重装 App Store 版 |
| 微信提示环境异常 / 弹出警告 | 微信自身检测到包被改动 | 本插件不做任何对抗检测；只能回滚到官方版 |

---

## 8. 回滚

1. TrollFools → 微信 → 卸载注入（或恢复原始 App）；
2. 需要完全干净：删掉微信，从 App Store 重装（会失去本地聊天记录，用第 1 节的备份恢复）；
3. 配置、日志、撤回记录都在微信容器里，重装微信会一起清掉。

---

## 9. 风险与合规（请先读完再决定）

- 往第三方 App 注入代码，属于微信用户协议不允许的行为，**账号存在被限制的风险**，请自行评估；
- 本插件不含、也不打算做任何破解付费功能、抢红包/资金自动化、游戏作弊、伪造点赞、模拟定位；
- AI 功能会把命中规则的聊天内容发往**你自己配置**的模型服务端，本项目没有自己的服务器、不收集数据；
- 日志默认不记录消息正文（只记长度），排错时再打开、排错后关掉。
